# Изолированный CAD: стадии задания и передача сетки

## Методика

Linux x86-64, Python 3.11.2, NumPy 2.4.6, OCP 8.0.1.1.0; временные системные библиотеки Qt/OpenGL доступны через `LD_LIBRARY_PATH=/tmp/qt-user-libs`. Это виртуальное окружение, не целевой компьютер пользователя и не Windows. Используются тестовые документы, не проект каркаса и не проверка безопасности. Данные — `weldment_job_stages.json` и `cad_transport_synthetic.json`.

Для первого опыта настоящий `WeldmentCadJob` пишет документ, создаёт отдельный процесс, ждёт его завершения и через обычный `CadJob` проверяет отчёт, ZIP и `CadMesh`. В каждой из семи пар запускается стандартный рабочий процесс и диагностическая обёртка, вызывающая его же `main` с обёртками времени; порядок чередуется. Перед сравнением полностью проверяются координаты, группы, экземпляры и счётчики сетки. Инструментация меняет загрузку модулей: диагностический процесс заранее импортирует `cad_free_arm` даже для снимка, а вызовы оборачиваются. Время от запуска родителя до входа в скрипт использует общий монотонный счётчик Linux; это не гарантия сопоставимости для другого окружения. Оба варианта остаются одноразовыми и изолированными, обычные проверки не отключаются.

Указаны медианы и минимум–максимум, миллисекунды. Интервалы перекрываются: например, импорт OCP и построение входят во время функции построения, валидации и триангуляции, а проверка `CadMesh` входит во время после ожидания. Медианы разных величин нельзя суммировать. Первое обращение к `OCP.BRepCheck` включает возможную инициализацию других модулей OCP, не только один класс. Время после возвращения `main` до окончания ожидания включает запись диагностического отчёта, завершение и очистку Python/нативного кода и задержку обнаружения завершения; оно не доказывает стоимость конкретного деструктора.

## Синтетическая передача больших сеток

Отдельный искусственный дочерний процесс создаёт массивы, 100 групп и NPZ; далее используется настоящий проверяющий загрузчик `CadJob`. Это **не** реальный CAD, STEP или несущий каркас. По десять повторов, одинаковые и полностью проверенные массивы. Ожидание процесса, генерация и запуск включены в общее время, поэтому сравнивать его с реальным CAD нельзя. После выхода включены чтение отчёта/ZIP, распаковка массива, проверки и очистка. Синтетические результаты до добавленных контрольных точек отмены:

Лимит типичного текущего сварного рычага — 100 000 треугольников; большие искусственные размеры нужны для общего транспорта и перспективных многогрупповых сцен.

Воспроизведение из `suspensionlab` с установленными зависимостями:

```sh
LD_LIBRARY_PATH=/tmp/qt-user-libs python diagnostics/weldment_job_stages.py --repeat 7
python diagnostics/cad_transport_synthetic.py --repeat 10
```

## Изменение безопасности и проверки

`CadJob` теперь повторно проверяет отмену после проверки ZIP, чтения метаданных, массива треугольников и индексов, перед конструированием `CadMesh` и после него; I/O-ошибка в уже отменённом задании сообщает отмену. Уже начатая операция NumPy сама по себе не прерывается, а очень поздняя отмена может произойти после финальной проверки; защита от устаревшего результата в UI по поколению по-прежнему нужна. Проверки архива, формата и значений сохранены, процесс по-прежнему одноразовый. Это не ускорение обычного успешного задания; при ранней отмене после завершения дочернего процесса можно не выполнять оставшуюся загрузку или валидацию.

Детерминированные многопоточные тесты приостанавливают чтение ZIP, метаданных и треугольников, а также проверку `CadMesh`, отменяют работу, проверяют отсутствие результата и удаление временного файла; отдельно проверено, что ошибки без отмены по-прежнему отклоняются. Linux/offscreen профиль транспорта, STEP, кеша, настоящего OCP и обоих редакторов — **145 passed** после дополнительных контрольных точек; отдельный UI профиль при 150% — **48 passed** до них. Ruff, mypy и `git diff --check` прошли. Полный набор после изменения не запускался; ручной тест, аппаратный OpenGL и Windows не проверялись.

Устойчивое ускорение повторных одинаковых запросов может дать ограниченный кеш результатов с полным ключом документа и качества, повторной проверкой актуальности, безопасной отменой, очисткой по закрытию и явным принудительным перестроением. Его нужно отдельно реализовать, измерить и проверить; эти результаты его ещё не подтверждают. Прогрев или постоянный CAD-процесс, досрочное завершение без обычной очистки и ослабление проверок не внедрялись: их влияние на изоляцию, сбои и Windows не установлено.
