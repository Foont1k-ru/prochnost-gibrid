# Подвеска.Про — этап M1 в разработке

Нативное офлайн-приложение на Python 3.11+ и PySide6. Это **не готовый инженерный калькулятор**: расчётное ядро двухрычажной подвески частично реализовано, подключено к экспериментальной таблице в окне, но не прошло независимую инженерную валидацию. Рекомендации и чертежи ещё не реализованы. Главная схема показывает исходную геометрию; в окне расчёта есть отдельная покадровая проекция выбранного результата и отдельное окно условного баланса. Проекты и шаблоны — локальные JSON-файлы.

## Предварительный обзор STEP

В меню **«Файл → Обзор состава STEP…»** можно локально выбрать распакованный текстовый `.step` / `.stp` размером до 64 МиБ. Окно перечисляет записи `PRODUCT` и прямые связи `NEXT_ASSEMBLY_USAGE_OCCURRENCE`, соединяя их через определения изделий, и показывает количества отдельных типов записей. Несколько вхождений одного изделия остаются отдельными связями. Незнакомые способы описания сборки могут быть пропущены; неразрешённые ссылки отмечаются. Кодировка не-ASCII байтов не определяется, часть старых STEP-последовательностей может не декодироваться. Файл и проект не изменяются; окно не сохраняет результат. RAR сначала необходимо распаковать самостоятельно.

Для некоторых прямых связей обзор дополнительно находит записи `ITEM_DEFINED_TRANSFORMATION` и выводит две связанные `AXIS2_PLACEMENT_3D`: начала и нормализованные оси с округлением. Поддерживается только одна явная цепочка ссылок; отсутствие, неоднозначность, неполные или вырожденные данные отмечаются, а не заменяются единичной матрицей. Частичные значения осей по умолчанию пока не поддерживаются. Порядок «1/2» — порядок ссылок в файле; он **не обозначает** системы родителя и детали. Контексты и единицы начал не установлены, направление преобразования и итоговая иерархия положений не вычисляются.

Обзор также частично сопоставляет два представления отношения с определениями родителя и дочернего изделия по прямым ссылкам `SHAPE_DEFINITION_REPRESENTATION` и `PRODUCT_DEFINITION_SHAPE`, отмечая обратный порядок, несовпадение, неоднозначность или пропуски. Он показывает номера контекстов и прямое наличие каждой системы в списках элементов представлений, если эти списки прочитаны. Одна система может упоминаться в обоих списках; отсутствие прямой ссылки не исключает других способов связи. Совпадение номера контекста не подтверждает единицы или корректность сборки. Сопоставление неполное и не устанавливает направление переноса тела.

Для найденных контекстов отдельно читается часть прямых объявлений SI-единиц длины через `GLOBAL_UNIT_ASSIGNED_CONTEXT` и `SI_UNIT`: показывается объявленный коэффициент в мм на единицу. Другие способы записи, включая дюймы через единицы преобразования, а также отсутствующие или неоднозначные данные отмечаются как не определённые; возможны неподдерживаемые контексты. Это не проверка всей сборки и не доказательство применимости единиц к конкретной системе: координаты в окне **не пересчитываются**.

Флажок **«Показать экспериментальные кандидаты преобразований»** в обзоре по умолчанию выключен. При включении он показывает для отдельных связей предположительную относительную матрицу `R` и перенос `t` в мм (`p′ = R·p + t`). Кандидат выдаётся только для определённых прямых связей, двух распознанных SI-контекстов с одинаковой единицей длины и прямых упоминаний систем в списках; при недостатке данных выводится причина отказа. Направление проверено на одном искусственном CAD-образце, но не доказано для произвольного STEP. Матрица округлена, глобальные положения вложенных деталей не вычисляются и результат не переносится в проект или геометрию. Произвольное положение исходной сборки не является установочным.

Это **не CAD-импорт и не проверка STEP**: тела не отображаются, преобразования сборки и единицы всей модели не разрешаются, свойства и размеры не извлекаются, связи не становятся шарнирами. Числа типов записей не подтверждают число корректных тел или корректность файла. Положение компонентов, система координат, масштаб и применимость для расчёта не установлены; координаты в проект автоматически не переносятся.

## Установка и запуск

### Пробная сборка Windows без установки Python

При успешном выполнении workflow **«Подвеска.Про — тесты Windows»** доступен артефакт `suspensionlab-windows-experimental`. На GitHub откройте вкладку **Actions**, выберите этот workflow и успешный запуск нужной ветки и коммита, затем в разделе **Artifacts** скачайте указанный архив (может понадобиться вход в GitHub). Полностью распакуйте архив и запустите `SuspensionLab/SuspensionLab.exe`; всю папку `SuspensionLab` необходимо сохранить вместе. В архиве есть инструкция и файл `BUILD-INFO.txt` с идентификатором сборки. Артефакты автоматически удаляются через 14 дней; если нужного запуска больше нет, потребуется новая сборка.

Сборка экспериментальная и не подписана: Windows может предупредить о неизвестном издателе. В CI проверяются обычный запуск и журнал, ресурсы, учебные расчёты хода и стабилизатора, графики и сводка, статический конфликт и его CSV, пересчёт одной точки силы амортизатора, путь условного баланса и запись/чтение временного проекта в режиме offscreen. Это не ручная проверка на чистом компьютере и не полноценный релиз. Расчётное ядро не прошло независимую инженерную валидацию. Проекты храните и копируйте отдельно от приложения. Если артефакт недоступен, ниже описан запуск из исходников.


### Windows: пробный запуск из исходников

Проверенного установщика или релизного `.exe` пока нет. На странице репозитория GitHub выберите нужную ветку в переключателе веток, затем **Code → Download ZIP**, распакуйте архив. Последние изменения могут находиться в ветке открытого PR, а не в `main`; ZIP с `win` в корне репозитория не является проверенной сборкой текущей версии.

Установите Python 3.12 для Windows (64-bit). Откройте папку `suspensionlab` внутри распакованного архива и откройте в ней PowerShell (например, в адресной строке Проводника введите `powershell` и нажмите Enter). При первом запуске выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Установка зависимостей требует интернета и может занять некоторое время; активация виртуальной среды для этих команд не нужна. При следующих запусках откройте PowerShell в этой же папке и выполните только последнюю команду. Для знакомства можно открыть шаблон «Кольцо» и выбрать «Расчёт → Ход колеса · двухрычажная…». Не используйте результаты для инженерных решений.

Linux/macOS:

```bash
cd suspensionlab
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m suspensionlab
```

Установку зависимостей необходимо выполнить заранее; сама программа не выполняет сетевых запросов. Для Linux необходимы системные библиотеки Qt и графическая сессия. Визуально протестировать интерфейс следует на целевой Windows: сборка и работа на чистой системе ещё не проверены.

## Проверки

```bash
python -m pytest -q
ruff check .
mypy suspensionlab
```

На машине без экрана Qt можно запускать с `QT_QPA_PLATFORM=offscreen`, если установлены необходимые системные библиотеки. В GitHub Actions отдельный workflow «Подвеска.Про — тесты Windows» устанавливает приложение, запускает Ruff, mypy и полный pytest, включая тесты Qt в режиме offscreen; отчёт pytest сохраняется как артефакт. Это автоматические тесты, не визуальная проверка и не сборка готового exe. Экспериментальная сборка PyInstaller доступна как временный артефакт CI после успешной автоматической проверки; это не проверенный релиз или установщик.

Промежуточные коммиты с маркером `[test-only]` запускают проверки Windows без упаковки нового приложения; для пробной сборки нужен успешный прогон коммита без этого маркера.

### Замер скорости кинематики

Команда `python -m scripts.benchmark_sweep --warmup 2 --repeat 7` из каталога `suspensionlab` измеряет отдельно кинематический свип готовой модели на 61 точке; метрики, интерфейс и экспорт не входят в замер. Результат зависит от машины и библиотек, а не является гарантией скорости приложения. Методика и пример локального замера приведены в `docs/benchmarks.md`.

## Диагностика и журнал

Журнал можно посмотреть через **«Справка → Открыть журнал»**. На Windows он находится в `%APPDATA%\SuspensionLab\logs\suspensionlab.log`; путь можно вставить в адресную строку Проводника. Файлы `.log.1` и далее — предыдущие части после ротации. Отправлять журнал заранее не требуется: если обнаружится проблема, полезно записать действия, сообщение и время ошибки, а при необходимости приложить журнал или скриншот.

Журнал может содержать имена и пути проектов, а также причины ошибок с численными значениями; перед передачей проверьте его и скройте приватные данные. Он не содержит полный проект и не записывает все действия, ошибки и расчётные данные; по одному журналу воспроизвести проблему может быть невозможно. При ошибке до начала работы приложения или при недоступной папке журнала файла может не быть. Приложение не отправляет журнал автоматически.

## Работа с проектом

Откройте шаблон, выберите точку/узел в дереве, измените значение в инспекторе, сохраните `.susp.json`. Вкладки показывают переднюю и заднюю оси и их условное совмещение. Отмена/повтор доступны через меню. Автосохранение раз в минуту записывает изменённый проект в единственный общий `autosave.susp.json` в каталоге настроек. Автоматического предложения восстановления при запуске нет. Каталог: `%APPDATA%/SuspensionLab` на Windows, `$XDG_CONFIG_HOME/SuspensionLab` или `~/.config/SuspensionLab` на Linux.

Проект и автосохранение сначала записываются во временный файл рядом с целевым, затем заменяют его. При обнаруженной ошибке до замены предыдущая версия сохраняется, а проект остаётся несохранённым. Это не замена резервному копированию: при потере питания, на сетевых или нестандартных файловых системах сохранность не гарантируется. После аварийного завершения может остаться временный файл `.suspensionlab-project-*.tmp`. Символическая ссылка остаётся ссылкой, заменяется её цель; жёсткие ссылки и специальные права доступа или ACL могут не сохраниться при замене файла.

### Восстановление автосохранения

Выберите **«Файл → Восстановить автосохранение…»** и подтвердите действие. Программа прочитает последнюю общую копию и при необходимости предложит сохранить текущие изменения. Копия может относиться к другому проекту или быть устаревшей; исходный путь и история отмены в ней не сохраняются. Восстановление открывает её как новый несохранённый проект, не заменяя исходный файл проекта. Применяется только полная копия текущей схемы 1.0; неполная, повреждённая или несовместимая копия отклоняется. Проверка структуры не является инженерной проверкой.

До первого сохранения восстановленной копии **под другим именем** автосохранение приостановлено, чтобы не перезаписать найденный файл. Следовательно, новые правки в этот период не защищены автосохранением — сохраните копию сразу. После сохранения под другим именем автосохранение снова работает и при дальнейших изменениях может перезаписать общий файл. Если отказаться от восстановленного проекта и открыть или создать другой, автосохранение также возобновится. Несколько одновременно запущенных экземпляров используют один общий файл и не координируются. Если восстановление не удалось, файл можно открыть обычным способом или исследовать отдельно; обычное открытие может дополнить отсутствующие поля значениями по умолчанию.

### Снимки настройки

Меню **«Правка → Сохранить снимок настройки…»** добавляет именованный снимок в текущий проект. Чтобы применить его, выберите **«Правка → Восстановить снимок настройки…»**, затем строку в списке и нажмите «Восстановить». Можно отменить операцию через «Правка → Отменить» и повторить её. Восстановление заменяет метаданные проекта, автомобиль и обе оси; текущие замки, настройки вида, модель B, список снимков и путь файла остаются прежними. Проект отмечается изменённым и не перезаписывается до сохранения. Снимки входят в файл проекта: для их сохранения сохраните проект.

Снимок использует сериализованные значения с округлением до четырёх знаков после запятой, а не полную внутреннюю точность. Повреждённый, неполный или несовместимый со схемой 1.0 снимок не применяется; проверка структуры не подтверждает физическую допустимость. Снимки не являются отдельными резервными копиями и не содержат результаты расчётных окон.

### Настраиваемые шаблоны

В меню «Создать из шаблона» выберите «Легковой автомобиль · настроить» или «SUV · настроить», затем компоновку двигателя, тип подвески каждой оси и ведущие оси. Для легковой заготовки начально выбран поперечный двигатель, для SUV — продольный с раздаткой; это можно изменить независимо от типа кузова. Для легкового автомобиля по умолчанию выбраны передний Макферсон с приводом и независимая задняя подвеска; сзади можно выбрать торсионную балку. Передний привод можно отключить для каждого из трёх типов. В этой упрощённой модели балка только неведущая; при её выборе задний привод отключается. Для SUV спереди доступны многорычажная и двухрычажная подвески, сзади многорычажная и неразрезной мост; передний и задний приводы включаются независимо, по умолчанию оба включены. Прежние шаблоны остаются в списке.

Все координаты и размеры — **учебные**, не параметры конкретного автомобиля. Макферсон и торсионная балка имеют собственные наборы точек и условные линии; балка не является жёстким ведущим мостом, её кручение не моделируется. У ведущей оси условно показаны линии полуосей и точка редуктора. На виде сбоку и сверху показана выбранная компоновка двигателя и привода; все агрегаты и карданы — только условный эскиз, их реальные положение и размеры не определены. Расчёта редуктора, кардана, передаточных чисел и передачи момента нет. Точки приводов сохраняются и при отключении привода, но на схеме не показываются; их наличие не означает, что ось ведущая. При открытии старого проекта недостающие стандартные точки дополняются учебными значениями, которые необходимо заменить измеренными данными.

**Выбор компоновки и виды.** Для существующего проекта выберите в дереве **«Автомобиль»**, в инспекторе — **«Компоновка двигателя и привода»**, а на соответствующих осях включите признак ведущей оси. Поперечная схема показывает только задний кардан при включённом заднем приводе; продольная схема с передним дифференциалом в КПП — также только задний; продольная с отдельной раздаткой показывает передний и/или задний карданы к включённым осям. В первых двух схемах задний привод без переднего отмечается несовместимым: подсказка появляется ещё в окне создания, затем предупреждение видно в панели диагностики. Нажатие на предупреждение открывает настройки автомобиля; включение ведущих осей находится отдельно в узлах «Привод» каждой оси. Предупреждение не блокирует создание или сохранение и относится только к выбранной условной схеме. Для старых проектов компоновка не задана, поэтому кардан скрыт до явного выбора; старые точки не меняются. Параметр сохраняется в проекте и снимках; предыдущая версия может проигнорировать его при пересохранении, сохраняйте резервную копию. Подробнее и источники — в `docs/powertrain_layouts.md`.

На основном холсте спереди колесо показано прямоугольным профилем ширины шины и диаметра, сбоку — кругом, сверху — прямоугольником. Это ортографическая условная форма без перспективы и учёта статических углов.

Расчёт Макферсона, многорычажной подвески, балки и моста отсутствует. Для двухрычажной доступна экспериментальная таблица в интерфейсе и Python API. Панель диагностики также напоминает об этих ограничениях. Категория задаёт начальную конфигурацию, но не сохраняется как отдельное свойство автомобиля; в файле сохраняются типы осей, флаги приводов и координаты.

### Расчёт в окне

Откройте проект с двухрычажной осью (например, старый шаблон «Кольцо»), затем меню **«Расчёт → Ход колеса · двухрычажная…»**. Выберите сторону и диапазон, нажмите «Рассчитать». Таблица показывает ход, развал и схождение. Для пружины и амортизатора отдельно включите допущение, что нижняя опора на нижнем рычаге, а верхняя — на кузове. Для пружины обязательно введите её измеренную длину в статике; длину смыкания и обе длины упоров амортизатора можно задать отдельно (ноль означает неизвестно). Параметры пружины берутся из проекта. Результаты и настройки окна не сохраняются в проекте.

Шаг таблицы по умолчанию до 1 мм, его можно уменьшить до 0,1 мм; диапазон ограничен ±100 мм и 401 точкой, продолжение решателя всегда не крупнее 1 мм. Приняты единицы мм, градусы и Н независимо от выбранных единиц инспектора. Сила в таблице — сила **самой пружины**, не суммарная нагрузка и не реакция шины. Длина пружины предполагается изменяющейся на столько же, на сколько изменяется расстояние её опор; преднатяг из проекта автоматически не учитывается. Неизвестные смыкание и упоры не проверены. При конфликте или неудачном решении смотрите столбец состояния: геометрическая сетка не останавливается автоматически на механических упорах. Изменение входов очищает старые результаты. Главная схема не анимируется; стабилизатор, приводы, отбойник, равновесие и динамика автомобиля в этой таблице пока не подключены.

Во вкладке **«График»** рядом с таблицей можно выбрать величину и выбрать ближайшую строку нажатием на график. Доступны также зазоры до явно заданных упоров и смыкания; их нет в таблице и её CSV. Выбранное значение под графиком округлено. Кнопка «Сохранить точки графиков CSV…» отдельно сохраняет все величины графиков и статусы для каждой строки, в том числе зазоры и пропуски; это не изображение графика. График использует исходные неокруглённые рассчитанные значения; таблица и её CSV показывают округлённые. Красный крест указывает на обнаруженный конфликт пружины или амортизатора, если соответствующая величина доступна. Отсутствие значения оставляет пропуск; участки с пропуском или обнаруженным конфликтом не соединяются. Линии между соседними точками — только визуальное соединение, не проверка промежуточной геометрии или безопасного хода. Отсутствие креста не подтверждает безопасность; неизвестные пределы не проверены. При изменении данных график очищается вместе с таблицей.

Во вкладке **«Сводка точек»** соседние строки с одинаковым статусом сгруппированы для навигации к первой или последней точке группы. Различаются отсутствие решения, обнаруженный конфликт/ошибка, неполные проверки и отсутствие конфликта по заданным пределам пружины и амортизатора. Если длина смыкания или упоры не заданы либо данные проверки недоступны, статус не считается полным. В двухстороннем исследовании учитываются обе стороны, а левый и правый ходы указаны отдельно. Это **не диапазоны безопасного хода**: промежутки, неизвестные пределы, столкновения и прочность не проверены; округлённые крайние точки не являются границами допустимости. Подробности каждой точки остаются в основной таблице.

При включении элементов окно показывает справочные параметры из проекта: свободную длину и характеристику пружины, а также длины амортизатора. Для проверки упоров и силы амортизатора используются только значения, явно введённые в этом окне: данные проекта не копируются автоматически. Подсказка обновляется при изменении проекта; числа в ней округлены.

Кнопка **«Перенести длины из проекта…»** позволяет явно заполнить оба предела амортизатора значениями выбранной оси. Сначала показываются старые и новые значения и требуется подтверждение; параметры проекта и коэффициенты демпфирования не меняются. Некорректные, выходящие за границы полей или требующие скрытого округления длины не переносятся. Перенос не подтверждает достоверность данных: шаблонные размеры могут быть условными, а реальные длины следует проверить между центрами креплений.

Кнопка **«Проверить статику»** отдельно рассчитывает положение при нулевом ходе и показывает результат во вкладке «Статика», даже если ноль не входит в заданный диапазон. Она не меняет рассчитанную таблицу и не проверяет демпфирование. Для включённой пружины дополнительно показаны расстояние между её точками в исходной геометрии и разница с заданной установленной длиной: это разные величины, их несовпадение само по себе не считается ошибкой. Для амортизатора показываются заданные длины упоров и расстояние между его точками. Изменение данных очищает результат. Это проверка только заданных элементов в одной точке, не доказательство равновесия, монтажной совместимости или безопасности.

После проверки доступен отдельный **CSV статики**: параметры и статус включённых элементов, координаты их опор для выбранной стороны, неокруглённые численные результаты и зазоры. Неизвестное или не рассчитанное показано прочерком, не нулём. Отчёт относится только к статике и не содержит полной геометрии — проект сохраняйте отдельно; в отчёт попадают имя и путь проекта, перед отправкой проверьте эти данные. При изменении входов или отказе проверки сохранение старого результата недоступно.

**«Разбор точки»** поясняет выбранную строку: свободную длину и характеристику пружины из проекта, почему сила может быть нулевой или не определена, расстояние опор и запасы до заданных упоров амортизатора. Подсказка свободной длины также видна до расчёта. Заданные длины амортизатора — полные расстояния между центрами креплений, не ход штока. Коэффициенты демпфирования задаются в Н·с/мм: 1000 Н·с/м = 1 Н·с/мм; сила при одной скорости не является полной характеристикой. Округлённые пояснения не проверяют равновесие, прочность, столкновения или промежутки между точками.

В CSV таблицы и графика хода теперь включаются параметры пружины из проекта (свободная длина, линейная жёсткость и прогрессивные точки, если заданы); отдельно преднатяг в расчёте не добавляется. CSV по-прежнему не заменяет файл проекта.

Если известны сила **на амортизаторе** и скорость его штока в одной точке испытания, кнопка **«Из силы и скорости…»** позволяет получить условный коэффициент `c = F / v` для сжатия и/или отбоя. Указываются неотрицательная сила в Н и положительная скорость штока в мм/с (например, 0,3 м/с = 300 мм/с), не скорость колеса. Каждое направление задаётся отдельной парой; пустая пара не меняет соответствующее поле. Результат предварительный и переносится только по кнопке «Применить». Одна точка не восстанавливает нелинейную кривую, гистерезис, трение или газовое усилие и не подтверждает пригодность для реальной подвески. При применении точки сила и скорость штока сохраняются в CSV таблицы и графика хода вместе с коэффициентом. При ручной правке коэффициента источник для этого направления сбрасывается и обозначается как не сохранённый; другой коэффициент не затрагивается. Данные остаются только в окне расчёта, в файл проекта не записываются. Перед отправкой отчёта проверьте имя и путь проекта.

Для силы амортизатора включите его и опцию линейной модели, затем **явно** введите мгновенную скорость колеса (мм/с; положительная — вверх) и коэффициенты сжатия и отбоя (Н·с/мм). Эта одна заданная скорость используется в каждой строке: это не движение во времени. Таблица покажет скорость сжатия, силу на колесо (положительная вверх) и рассеиваемую мощность. Упоры с нулевыми пределами не проверены; на обнаруженном упоре сила не выдаётся. Модель не учитывает газ, трение, гистерезис, клапаны, нагрев, шины или прочность и не включается в баланс сил.

График также доступен в окне исследования стабилизатора: по горизонтали — ход **левого** колеса, ход правого зависит от режима и указан в таблице. Можно выбрать угол плеча, скручивание, момент, усилие стойки, а также длины и зазоры элементов для каждой стороны. Для парных величин флажок «Сравнить с другой стороной на одной шкале» показывает обе стороны: сплошная линия с кругами — выбранная, пунктир с квадратами — вторая. Масштаб общий, пропуски каждой стороны обрабатываются независимо; при обнаруженном конфликте любой стороны обе серии разрываются. Общий момент и скручивание не имеют парной величины. Для противоположного хода по горизонтали по-прежнему указан ход левого колеса: ход правого имеет другой знак, не путайте оси. Зазоры не входят в таблицу и её CSV, но входят в отдельный CSV точек графиков; значение под графиком округлено. Проверки пружины и амортизатора учитываются только если они включены и выполнены; крест означает обнаруженный конфликт хотя бы на одной стороне. Если проверка недоступна, это не означает отсутствия конфликта.

### Условный баланс одной стороны

Откройте **«Расчёт → Условный баланс пружины · двухрычажная…»**. Выберите ось и сторону, явно задайте нагрузку **на одну сторону** в Н, измеренную длину пружины в статике и интервал хода. Жёсткость, свободная длина и прогрессивная характеристика берутся из проекта; нижняя опора считается прикреплённой к нижнему рычагу, верхняя — к кузову. Ноль в поле длины смыкания означает, что оно неизвестно и не проверяется. Для проверки упоров амортизатора включите её и задайте обе длины; если не включена — упоры не проверяются.

Поиск бисекцией требует смены знака невязки на концах интервала, останавливается при ширине до 0,1 мм и выдаёт границы, невязки и рассчитанную оценку середины. Это **не допуск по силе**. От статики до оценки проверяются заданные ограничения по точкам с шагом не более 1 мм; обнаруженная ошибка или несовпадение ветви прерывает расчёт. Кнопка «Точки проверки пути…» показывает только уже рассчитанные точки от статики к оценке: ход, пружину, зазоры, силу, невязку и состояние заданного амортизатора. Если проверка пути прервалась, окно показывает полученные до отказа точки и отдельно причину и место отказа; если точек нет, таблица пуста. Проверка несовпадения ветвей также отмечается как отказ, а не подтверждение доступности. Во вкладке «График» этого окна можно посмотреть невязку, силу, длины и известные зазоры только по сохранённым точкам; выбор точки связан с таблицей. Линия нулевой невязки — ориентир, не доказательство равновесия или устойчивости. При несовпадении ветвей последняя сохранённая точка отмечается крестом, а результат баланса не выдаётся. График использует неокруглённые данные; CSV таблицы пути содержит округлённые значения, а отдельный CSV точек графика — исходные значения float и статус проверки, включая отказ и пустой результат. Недоступные значения остаются пропусками; количество знаков не подтверждает физическую точность. Если ошибка возникла раньше проверки пути, кнопка недоступна. Прочерк означает отсутствие данных, а не нулевой зазор. Значения округлены, около границ необходим реальный запас. Непроверенные промежутки, единственность, непрерывная достижимость и устойчивость не доказаны. Отбойник, силы шины, стабилизатор и демпфирование в этом окне не включены; преднатяг автоматически не добавляется. Это экспериментальная модель и не расчёт дорожного просвета или инженерной пригодности. Результат не записывается в проект и очищается при изменении данных. После успешного расчёта кнопка «Сохранить результат CSV…» сохраняет показанные округлённые значения, введённые параметры, сериализованные параметры пружины, настройки поиска, ограничения и отпечаток модели; при ошибке результата экспорт недоступен. CSV итога не содержит таблицу точек пути. В окне точек доступен отдельный «Сохранить точки пути CSV…»: он сохраняет видимые строки и статус проверки вместе с параметрами и ограничениями. При отказе в нём указаны вид и причина отказа и оба значения хода; если точек нет, файл содержит метаданные и заголовки без строк. Это диагностический отчёт, а не успешный результат баланса. Проект с полной геометрией нужно сохранить отдельно.

### Просмотр движения в окне расчёта

После расчёта выберите строку таблицы, двигайте ползунок или нажимайте «Шаг»: справа показана фронтальная проекция выбранного положения. Масштаб одинаков для всего рассчитанного диапазона. Синим показаны рычаги и кулак, зелёным — условное обозначение пружины, оранжевым — амортизатор; пружина и амортизатор отображаются только если в расчёте явно включено крепление на нижнем рычаге. Контур колеса и витки условны, не чертёж. Зелёная линия соединяет опоры: введённая длина пружины может отличаться от расстояния между ними. Можно вручную перемещаться по точкам или нажать «Просмотр» и задать частоту кадров. Это проигрывание рассчитанной сетки, а не моделирование времени или реальная скорость подвески; отсчёт начинается с выбранной строки и идёт до конца таблицы.

Переключатель над схемой открывает **«3D-каркас»** этой же рассчитанной стороны. Удерживайте левую кнопку мыши для вращения, колесо мыши меняет масштаб, кнопка сбрасывает камеру. Масштаб по умолчанию общий для всех доступных кадров. Синий — рычаги и кулак, фиолетовый — рулевая тяга, зелёный — линия опор пружины, оранжевый — амортизатор, серый — условный цилиндр колеса. Изображение не использует STEP-модель, не представляет реальные детали, не рассчитывает контакт, столкновения или деформации. Строка и ползунок управляют тем же дискретным расчётом; смена вида приостанавливает просмотр.

Схема показывает и положения с обнаруженным конфликтом упора или смыкания витков: такие строки **не являются физически допустимыми**, проверяйте подпись и столбец состояния. Отсутствие предупреждений не подтверждает пригодность конструкции. Если точка не решена, изображение очищается. Стабилизатор на этой схеме не показан; совмещённый просмотр обеих сторон доступен в отдельном окне стабилизатора.

Автоматический просмотр в обоих окнах останавливается **перед обнаруженной в следующей строке** ошибкой геометрии, смыканием пружины или упором амортизатора, если эти компоненты включены и их пределы заданы. Ручной переход на такую строку оставлен для диагностики; запуск с неё будет отклонён. Изменение проекта или параметров очищает результаты и останавливает проигрывание. Проверяются только рассчитанные точки и явно заданные ограничения, а не весь непрерывный путь, поэтому проигрывание не подтверждает безопасность или достижимость положения.

### Сохранение таблицы

В CSV точек графиков сохраняются все величины, а не только выбранная, и отдельный признак обнаруженного конфликта. Числа записываются из внутренних значений float без округления таблицы: это не означает такую физическую точность. Прочерк — отсутствующие данные. Необнаруженный конфликт не подтверждает безопасность; статусы и введённые параметры должны читаться вместе с ограничениями. Для стабилизатора записаны ходы обеих сторон; CSV точек пути дополнительно содержит итог и подробности отказа. Этот файл не содержит весь проект; сохраняйте проект отдельно.

В обоих табличных окнах после расчёта доступна кнопка **«Сохранить таблицу CSV…»**; отдельное окно условного баланса сохраняет результат кнопкой «Сохранить результат CSV…», а просмотр пути — отдельной кнопкой «Сохранить точки пути CSV…». В таблицах экспортируются видимые строки с тем же округлением, включая ошибки, конфликты и обозначение отсутствующих значений «—»; в балансе — только успешный результат в показанном округлении, не внутренняя точность. В начале файла сохраняются параметры окна, название и путь проекта, признак несохранённых изменений, отпечаток сериализуемой модели и ограничения расчёта. Полный набор координат в CSV не входит: сохраните сам проект отдельно. Файл создаётся локально, в UTF-8 с BOM и разделителем `;`; при импорте в табличную программу может понадобиться указать эти параметры и десятичную точку. Текстовые значения, похожие на формулы, экранируются апострофом. Вблизи границы отображаемый зазор может округлиться до нуля с обеих сторон, при этом статус определён по неокруглённому значению. Из-за численных различий независимые вычисления непосредственно у границы могут дать разные статусы; необходим реальный инженерный запас.

### Стабилизатор в окне

В меню **«Расчёт → Стабилизатор и стойки · двухрычажная…»** отдельно задайте координаты X и Z оси и крутильную жёсткость стабилизатора; из проекта они не угадываются. Выберите одинаковый или противоположный ход колёс и нажмите «Рассчитать». Шаг по умолчанию 1 мм, минимальный 0,1 мм, не более 401 строки. В таблице показаны координаты концов левой и правой стойки, углы плеч, скручивание, момент и силы на стойках (плюс — сжатие, минус — растяжение).

Это отдельная **идеализированная** модель: ось параллельна Y, стойки и плечи жёсткие, нижние опоры на нижних рычагах, геометрия зеркальна, кузов неподвижен. Противоположный ход не является расчётом крена; реакции, столкновения, шарниры и прочность не проверяются. Продолжение начинается от статики, после первого отказа последующие строки не рассчитываются. Координаты и жёсткость надо измерить или задать в отдельном сценарии; табличный расчёт не сохраняется и не изменяет проект, к равновесию автоматически не добавляется. Справа от таблицы ползунок, кнопки «Шаг» и выбор строки позволяют вручную просматривать обе стойки и плечи по точкам; доступны виды спереди Y–Z и сверху Y–X. Масштаб каждого вида постоянен по рассчитанному диапазону. Синие линии — рычаги, серый стержень — условная ось, оранжевые линии — плечи, розовые — стойки. Ось показана прямой: её скручивание видно по числу в таблице, а не как деформация. Координата X скрыта на виде спереди, а Z — на виде сверху, поэтому часть движения в каждой проекции может быть незаметна. При отказе строки изображение очищается. При желании отметьте «Показать пружины» и/или «Показать амортизаторы»: это явное допущение о нижних креплениях на рычагах и верхних на кузове; пружины обозначены зелёным, амортизаторы — фиолетовым. Они отображают только положение опор, причём реальная длина пружины может отличаться от расстояния опор. Для проверки смыкания задайте статическую длину пружины и длину смыкания; для проверки амортизатора — обе длины упоров. Значения применяются одинаково к обеим сторонам и только при включении соответствующего элемента. Ноль означает, что значение неизвестно; неизвестные пределы не проверяются. Таблица и подпись показывают состояние каждой стороны, в том числе обнаруженные конфликты. Длина пружины изменяется на величину изменения расстояния её опор. Это дискретная проверка только заданных ограничений; силы пружин и амортизаторов в этом окне не рассчитываются, и совмещённая геометрия может быть физически недопустимой даже без замечаний. Решатель не останавливается на обнаруженных упорах: строка за упором показана диагностически, а не как разрешённое положение. При ошибке геометрии подвески отдельно выводится предупреждение, остаётся только стабилизатор. Кнопка «Просмотр» автоматически перелистывает рассчитанные точки, а частота кадров регулирует только скорость просмотра; это не симуляция времени.

## Инженерное ограничение

Предполагается кинематическая модель с жёсткими звеньями и идеальными шарнирами; податливость сайлентблоков, деформации и прочность не учитываются. Приложение не заменяет прочностной расчёт, натурные измерения и согласование с конструктором. До реализации и валидации следующих этапов не используйте его для инженерных решений.

Описание структуры сериализованного файла находится в `suspensionlab/resources/schema/project-1.0.schema.json`. Это базовая структурная схема, не инженерная валидация; полный прогон JSON Schema при загрузке пока не выполняется.

## Разработка ядра M1

Независимое от интерфейса ядро двухрычажной подвески находится в `suspensionlab/core/double_wishbone.py`; его ограничения и формулы описаны в `docs/formulas.md`. Этап M1 не завершён; главная схема показывает исходную геометрию, а таблица и её отдельная проекция используют только часть ядра. Проверка только ядра, без Qt:

```bash
python -m pytest tests/test_kinematics.py -q
```

Дополнительно `tests/test_independent_spatial_solver.py` сравнивает заданные учебные 3D-геометрии, проекционные метрики и их производные со второй численной реализацией расстояний и поворота. Тесты `tests/test_coordinate_invariance.py` отдельно проверяют согласованность при переносе и повороте учебной геометрии вокруг вертикали. `tests/test_singular_geometry.py` проверяет отдельные случаи потери ранга и отказа возле предела учебного механизма. Это проверка согласованности одинаковой математической постановки, не сравнение с CAD или измерениями; ограничения описаны в `docs/formulas.md`.

Для полного набора тестов требуется рабочая среда Qt. Из рабочего каталога `suspensionlab` можно также вызвать библиотеку напрямую:

```python
from suspensionlab.model.templates import load_template
from suspensionlab.core.double_wishbone import DoubleWishbone
from suspensionlab.core.metrics import corner_metrics

model = DoubleWishbone(load_template("ring").front)
pose = model.solve(30.0)
print(corner_metrics(model, pose))
```

При наличии измеренной длины пружины и заданной нагрузки можно отдельно оценить баланс одной стороны:

```python
from suspensionlab.core.equilibrium import SpringEquilibrium

axle = load_template("ring").front
# Пример условных входов, не готовые данные автомобиля.
problem = SpringEquilibrium(axle, static_spring_length_mm=230, coil_bind_length_mm=150)
sample = problem.evaluate(travel_mm=0, load_n=1000)
print(sample.wheel_support_n, sample.residual_n)
# find(load_n, from_travel_mm, to_travel_mm) требует на концах разные знаки невязки.
# path_step_mm=1 (по умолчанию) проверяет известные ограничения до корня по сетке.
# path_step_mm=None явно отключает проверку пути.
```

Результат не определяет фактический дорожный просвет или устойчивость и не учитывает шину и другие силы. Упоры амортизатора в поиске равновесия проверяются только при явно заданных креплении и длинах. Идеализированный отбойник можно включить явно через `bump_stop=BumpStopCharacteristic(...)`; без этого он не моделируется. В `analyze_corner` отдельно доступна проверка амортизатора при явно заданных креплении и длинах упоров; она проверяет только рассчитанные точки и не ограничивает движение автоматически. Поиск равновесия по умолчанию выборочно проверяет путь с шагом до 1 мм; проверяются только заданные ограничения, допустимость всей траектории не доказана. Описание всех допущений — в `docs/formulas.md`.

Показать учебную таблицу по пружине, амортизатору и стойкам стабилизатора с шагом 1 мм (после установки зависимостей, из каталога `suspensionlab`):

```bash
python -m examples.dense_sweep_demo
```

Таблица показывает обе стороны: сжатие пружин, длины амортизаторов, условные силы амортизаторов на колёса, плечи и стойки стабилизатора. Заданные мгновенные скорости колёс (+20/−20 мм/с) одинаковы для каждой строки, а не получены из симуляции времени. Коэффициенты линейного демпфирования сжатия/отбоя (2/4 Н·с/мм), положение оси стабилизатора, жёсткость и длины **условные, не измеренные**. Это пока не результат в окне приложения. Модель не проверяет прочность, шарниры и столкновения.

Отдельный API `evaluate_linear_damping` вычисляет силу и рассеиваемую мощность только при явно заданной скорости и характеристике. Он не моделирует клапаны, гистерезис, нагрев или реакцию упоров и не подключён к поиску равновесия; формулы и знаки — в `docs/formulas.md`. Если пределы амортизатора не заданы, флаг результата `stroke_limits_checked` равен `False`.

Прямой вызов `corner_metrics` по умолчанию принимает нулевые статические углы; `analyze_corner` использует настройку проекта, считая стороны симметричными. Пятно контакта приближается проекцией центра колеса на землю. Не используйте эти результаты для эксплуатации или проектных решений без независимой инженерной проверки.
